01 / Input & preprocessing

Separate the channels.
Remove the scan borders.

The input contains three vertically stacked exposures in B, G, R order. I keep blue fixed and estimate a separate integer translation for green and red; the algorithm does not estimate rotation or scale.

01

Preserve the input bit depth

The scan is loaded with cv.IMREAD_ANYDEPTH. I convert 8-bit values to float32 and divide by 255; 16-bit scans are divided by 65,535. This preserves the TIFF intensity range while putting both formats on the same [0, 1] scale.

02

Split with floor division

For a scan of height H, each channel has height floor(H / 3). The first band is blue, the second green, and the third red. Any remaining rows after the third equal-sized band are discarded.

03

Crop 10% before alignment

crop_border removes floor(0.1h) rows from the top and bottom and floor(0.1w) columns from the left and right of each band. The purpose is to keep the dark or bright plate borders from dominating the similarity score. This is a fixed crop applied to every image.

04

Use one coordinate convention

Throughout this report, a displacement is (row shift, column shift). The first value moves along the rows (down is positive); the second moves along the columns (right is positive). This is the order used when applying the displacement to array axes 0 and 1.

02 / Single-scale alignment

Exhaustive search
with normalized correlation.

The function align tests every integer shift in [−20, 20] on both axes: 41² = 1,681 candidates per channel. For each candidate, it compares the shifted source against blue and keeps the displacement with the lowest loss.

Why NCC?

The file defines both squared L2 error and NCC, but both execution modes call ncc_loss. No L2 results are used in this report. Squared L2 compares absolute pixel values; NCC first removes each patch’s mean and divides by its Euclidean norm, reducing sensitivity to a uniform brightness offset and positive contrast scaling.

Ŝ = (S − mean(S)) / ‖S − mean(S)‖₂
L(S, T) = −⟨Ŝ, T̂⟩

The negative sign makes maximizing correlation equivalent to minimizing the loss. Normalization is recomputed on the valid overlapping patches for each candidate, not once on the entire channel.

Exclude the pixels wrapped by np.roll

np.roll wraps pixels from one edge to the opposite edge. Those pixels have no valid correspondence in the target and must not contribute to the score. For a candidate displacement (row shift, column shift), let r denote the row shift and c denote the column shift. Both arrays are sliced to the same valid output coordinates:

rows: [max(r, 0), min(h + r, h))
cols: [max(c, 0), min(w + c, w))

For example, shifting down 5 and left 3 means scoring rows [5, h) and columns [0, w − 3). The top five rows and rightmost three columns contain wrapped pixels, so they are excluded. The overlap changes with the candidate shift.

Single-scale results · intensity NCC

G and R are translations relative to blue, in (row shift, column shift) pixels. These JPEG results use raw intensity values; edge features are used only in the pyramid mode. Select a result to view the original-resolution output.

03 / Multi-scale search

Coarse-to-fine alignment
with an image pyramid.

A ±20-pixel search cannot capture every TIFF displacement: the final red-channel shift for Melons is (177, 13). Expanding a brute-force search at full resolution would increase both the number of candidates and the cost of each comparison.

Four resolutions from three reductions

The program calls pyramid_align with layer=3. Each recursive call applies cv.pyrDown to the intensity images, approximately halving both dimensions with smoothing before subsampling. This produces four resolutions: full size, 1/2, 1/4, and 1/8. The broad search runs at 1/8 resolution.

Double the estimate, then add a residual

At the coarsest level, the function calls align, whose default search radius is 20. At each finer level, the previous displacement is multiplied by two. The function then evaluates residual shifts within ±8 of that prediction and returns the best complete displacement.

dfine = 2dcoarse + δ
δrow, δcolumn ∈ {−8, …, 8}

The total is 1,681 + 3 × 289 = 2,548 candidate scores per channel, with the largest search performed on roughly 1/64 as many pixels. The reachable displacement bound is ±(20 × 8 + 8 × 4 + 8 × 2 + 8) = ±216 per axis. This is a bound on the search path, not an exhaustive search of that full window: a wrong coarse match can place the correct alignment outside a later ±8 refinement window.

04 / Feature matching

NCC on Sobel
gradient magnitudes.

Mean subtraction and normalization compensate for global brightness and contrast differences. They do not make channels identical when different materials change brightness differently under red, green, and blue filters. The pyramid therefore matches edge magnitude instead of intensity.

What edge computes

edge uses two 3 × 3 Sobel filters to estimate horizontal and vertical derivatives in float32, then returns their magnitude. The feature emphasizes locations with a strong spatial change and discards the sign of that change.

Gx = Sobelx(I), Gy = Sobely(I)
E(I) = √(Gx² + Gy²)

Where it enters the pyramid

The recursion downsamples the intensity images first. At each resolution, it computes fresh edge magnitudes for both source and target and evaluates NCC on those edge maps. The returned shifts are finally applied to the original cropped intensity channels, so the reconstruction retains the original colors.

Emir at 1/8 resolution after the initial border crop. The intensity images use the original [0, 1] scale; edge maps are independently scaled for display only. NCC operates on the computed floating-point features. These views show the representation used for matching, not an intensity-versus-edge performance comparison.

05 / Reconstructing RGB

Crop the shared overlap.
Remove wraparound exactly.

The initial 10% crop removes scan borders before matching. After applying the final translations, a second crop keeps only coordinates valid in all three channels. These two crops solve different problems.

Intersect the three valid regions

Let the cropped blue channel have shape (h, w), with green and red shifts (rG, cG) and (rR, cR), each in (row shift, column shift) order. Here r denotes a row shift and c denotes a column shift. Blue is unshifted. The common rectangle is:

top = max(0, rG, rR)
bottom = min(h, h + rG, h + rR)
left = max(0, cG, cR)
right = min(w, w + cG, w + cR)

The same half-open slice [top:bottom, left:right] is taken from blue and both shifted channels. This removes all rolled-in pixels without imposing an extra fixed margin.

Combine and save the channels

The three valid arrays are stacked in R, G, B order. Values are multiplied by 255, clipped, and converted to uint8. Because OpenCV writes images in BGR order, the RGB array is converted to BGR immediately before saving the JPEG. No white-balance or contrast adjustment is applied.
